## 1. 关键补充发现

### 1.1 KB 来源章节比此前提取的更完整，存在覆盖缺口（最高优先）
- **五、百问百答（3.0）** 共 **25 条主疑虑**（1–25），且 5/6/7/8/9/12/13/14/18/19 还带 2–4 个子项，**合计约 45 个问答对**。
  - 此前 KB-QA = **28 条**，明显少于文档可用的 ~45 条 → **至少约 17 个问答对未入库**（如「签合同」「被骗多了」「网上说骗人」「客户信息保密」「是不是医生」「明天再付」「吃出问题找谁」「没检查过」「别人说话听不清」「考虑商量」等均未覆盖）。
- **八、耳病专业知识** 有 **8.1–8.7 七个子主题**，且粒度很细（8.3 含 3 个分类维度、8.4 听力损失 5 级、8.6 中耳炎 4 类+中医证型、8.7 美尼尔）。
  - 此前 KB-MED = **15 条**，对 8.3/8.4/8.6 的细分维度覆盖偏薄 → **建议扩到 ~22–25 条**以承载分类粒度。
- **结论**：KB 应**直接从五/八重新派生**，而非沿用旧 PDF 提取；这是性价比最高的补齐动作。

### 1.2 SOP 自身话术与 A8 合规守门**自相矛盾**（关键风险）
- SOP 在「步骤3 客户信息收集」明确教客服说：**「俗话说久鸣必聋，久聋必呆……只会越拖越严重，甚至造成耳聋」**——这正是 A8 红线 **B（恐吓/制造焦虑）**。
- SOP 在「五、百问百答」多处用 **「国药保疗效，国药保安全」「效果方面您尽管放心」**——这靠近 A8 红线 **疗效承诺**。
- 但 SOP 在 9.1 又正确地说：**「任何承诺给您 100%治疗好的机构都是忽悠您的」**。
- **冲突后果**：若 AI 坐席**逐字照搬** SOP 成交话术，A8 会在「促开口/出方案/报价」阶段**把自家话术拦下来**，漏斗直接断在腰部。
- **解法（二选一或并存）**：
  1. 给坐席 Agent 喂**「合规净化版」** SOP 话术（保留医学逻辑、去掉恐吓/绝对化措辞）；
  2. A8 的 B 线做**语义分级**——区分「科普性风险提示（允许）」与「恐吓式胁迫/绝对承诺（拦截）」。当前 `evaluate_compliance` 命中即拦，需要先把这条规则细化，否则会误伤正常科普。

### 1.3 「报价」阶段卡在 B8（价格/剂量）——需区分商业披露 vs 医疗违规
- SOP 报价原文：**「原价 1280 元……优惠价 598 元」「先办 48 元药品定金，剩下货到付款」**。
- 这是**合法商业价格披露**，但当前 A8 的 **B8（未审价格/剂量）** 只要出现「元/盒/疗程/mg」就拦 → **漏斗必然死在报价步**。
- **必须**把 B8 收窄为：拦截「疗效+价格捆绑承诺」（如「一个疗程保证治愈仅 XX 元」），放行「单纯价格/定金/货到付款说明」。

### 1.4 标签 taxonomy（六）可直接固化为 `setMorphixTag` 受控词表
SOP 已给出完整标签体系，目前编排里 `setMorphixTag` 节点**有节点类型但无词表**，应落地：
- **推广标签**：开口/未开口/其他；未成交/成交；报价类/称签/有效开口(≥3句)/无效1(同行媒体职能)/无效2(小孩误点)/禁止开发(≥90岁/重症/未成年)
- **流程标签**：客户信息收集 / 下结论出方案 / 通天草 / 提要求 / 给信心发案例 / 报价 / 成交
- **疑虑标签**：价格 / 效果 / 原理 / 服务 / 机构 / 产品
- **层级标签**：A重点挖掘(30天内) / B重点保持(30-60) / C重点挽回(60-90) / D重点沉睡(90天外)
- **售后标签**：禁止跟进(售后通知) / 恶意订购(拒签2次)
- 规则多为「N选1 / 可多选 / 动态改写」，正好对应 `setMorphixTag` 的枚举约束。

### 1.5 客户画像（七）可直接固化为 `setCustomerAttr` 结构化字段
- 维度：症状特征（声音类型/响度/持续性/单双侧/伴随症状/诱因）、人口统计（年龄/性别）、听力情况（是否检查过/听力图结论）、购买力与消费行为、画像类型（核心=焦虑中年高压职场人 / 次级=年轻耳机族·老年听力衰退·突聋后遗症）。
- 这是「信息收集」步骤（一·步骤3 的 8 问）的结构化落库目标，当前编排未定义字段 schema。

### 1.6 多轮触达（三/四）需要**定时 + 分支**能力，而当前 runtime 引擎只支持单分支
- 三（当天3次：30min/14:00/20:00）、四（Day2/3/4 分层）本质是**延时触发 + 按响应分支**。
- 现状：`_step_nodes` 只跟 `nexts[0]`，**无 delay 节点、无 branch 节点** → 无法直接编排养育序列。
- 这是之前 follow-up「把 A0 改成路由中枢」的同一种能力缺口：引擎需补 **timer / switch(按标签或意图)** 节点类型。

### 1.7 成交信号识别（九）+ 疑虑分类（六）是现成的 `multiJudge` 场景
- 九的「五个信号」（挑刺/问题多/对比/讲价/反复纠结）本质是对话意图分类 → 命中即路由到「逼单 Agent」。
- 六的「疑虑标签」是另一类分类 → 路由到对应答疑/案例话术。
- 二者都能用编辑器已有的 `multiJudge` 节点承载，目前未启用。

## 2. 已落地能力 vs SOP 的完整度雷达

| SOP 能力 | 状态 | 缺口 |
|---|---|---|
| KB-QA（答疑） | ✅ 28 条，但**偏少** | 重派生至 ~45 |
| KB-MED（专业知识） | ✅ 15 条，粒度偏薄 | 扩至 ~22–25 |
| A8 合规守门 | ✅ 真拦截 | B 线需分级；B8 价格需豁免商业披露 |
| 标签体系 | ⚠️ 节点有、词表无 | 固化六的 taxonomy |
| 客户画像 | ⚠️ 节点有、schema 无 | 固化七的字段 |
| 成交漏斗主流程 | ⚠️ 仅 A8 点亮 | 需补全 11 步节点图 |
| 多轮触达调度 | ❌ 引擎不支持 | 需 timer/switch 节点 |
| 意图/信号分类 | ❌ 未启用 | 用 multiJudge 接九/六 |

## 3. 建议的下一步（按 ROI 排序，均可执行）

1. **重派生 KB（五→KB-QA ~45 / 八→KB-MED ~22）**——直接消缺口，半小时级。
2. **固化标签词表 + 客户画像 schema**——把六/七落进 `setMorphixTag`/`setCustomerAttr` 定义。
3. **A8 B 线分级 + B8 价格豁免**——避免守门误伤 SOP 正常话术与合法报价。
4. **合规净化版 SOP 话术**——给坐席 Agent 的副本去掉恐吓/绝对化措辞。
5. **完整 11 步漏斗节点图**——用现有 nodeType（userInput/aiChat/kbSearch/multiJudge/msgOutput/setMorphixTag/setCustomerAttr/interruptBefore）铺满一·二。
6. **引擎补 timer + switch 节点**——解锁三/四的养育序列与 A0 路由（较大改动，建议单独排期）。
