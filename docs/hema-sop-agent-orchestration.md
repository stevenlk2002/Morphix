# 河马客服部 SOP → AI 智能体工作流编排方案

> 源文档：企微文档《河马客服部标准化运营执行手册》（本地文字版 `AI study/河马大健康销售SOP/河马大健康销售SOP_文字版.pdf`，39 页）
> 编排目标：把「一个客服从加微到交接医助」的全链路，拆成可被 Morphix 编排引擎调度的节点，并明确每个节点是 **AI 智能体 / 规则引擎 / 人工** 承担。
> 版本：v1.0 ｜ 2026-08-03

---

## 0. 结论速览

原 SOP 共 9 章，映射为 **17 个流程节点**，自动化分级如下：

| 承担方 | 节点数 | 节点 |
|---|---|---|
| 🤖 **AI 智能体主导** | 7 | 破冰触达、问诊采集、异议应答、成交信号识别、标签打标、画像推断、沉默唤醒 |
| ⚙️ **规则引擎/模板**（不需要 LLM） | 5 | 欢迎语、依从性告知、报价发布、交接铺垫触发、跟进节奏调度 |
| 🧑 **人工/药师强制介入** | 3 | 诊断结论确认、用药方案审批、收款与议价 |
| 🛡️ **AI 网关（旁路必过）** | 2 | 合规守门、会话质检 |

**核心判断**：这条 SOP 里 AI 的最高价值不在「替人说话」，而在
1. **问诊采集**（步骤3 的 8 问）——结构化槽位填充，机器比人稳定；
2. **百问百答**（第五章 25 类异议）——RAG 检索，比人翻话术库快；
3. **标签管理**（第六章 4 类必选标签）——人工打标最容易漏，AI 全自动；
4. **成交信号识别**（第九章 5 个信号）——人最容易错过的「临门一脚」时机。

**核心红线**：步骤4「下结论」、步骤5「出方案」、步骤8「报价」这三步 **AI 只能出草稿，禁止直发客户**。这既是医疗合规要求，也是这条 SOP 目前风险最集中的地方（详见 §5）。

## 1. SOP 解构：9 章 → 17 节点

### 1.1 原文档结构

| 章节 | 内容 | 性质 |
|---|---|---|
| 一、企微新线成交SOP（4.0） | 步骤 1–11，从欢迎语到交接铺垫 | **主流程** |
| 二、报价后沉默电话促单SOP（2.0） | 第 2 天电话促单 8 段话术 | 分支流程 |
| 三、当天3次触达促开口SOP（2.0） | 30min / 14:00 / 20:00 三次触达 | 分支流程 |
| 四、前3天互动促开口SOP | 第 2/3/4 天三封信 | 分支流程 |
| 五、百问百答（3.0） | 25 类客户疑虑 | **知识库** |
| 六、标签管理 | 推广/流程/疑虑/层级/售后 5 组标签 | **状态机定义** |
| 七、客户画像 | 耳鸣客户 7 维画像 + 3 类次级画像 | **知识库** |
| 八、耳病专业知识 | 8.1–8.15 病理/听力图/合并症/药品 | **知识库** |
| 九、五个信号该逼单了 | 挑刺/多问/对比/砍价/纠结 | **策略规则** |

> 关键洞察：五、七、八三章**不是流程**，是知识底座；六章**不是流程**，是状态机的状态定义。真正的流程只有一、二、三、四、九。很多团队把 SOP 直接喂给大模型效果差，就是因为没做这一层拆分。

### 1.2 17 个流程节点

| # | 节点 | 来源 | 承担方 | 触发条件 |
|---|---|---|---|---|
| N01 | 欢迎语 + 意向分流 | 步骤1 | ⚙️ 规则 | 好友添加成功 |
| N02 | 破冰触达（当天3次） | 三 | 🤖 Icebreaker | +30min / 14:00 / 20:00 未开口 |
| N03 | 阶梯信任（第2–4天） | 四 | 🤖 Icebreaker | 当天3次仍未开口 |
| N04 | 有效开口判定 | 六·推广标签 | 🤖 Tagger | 每条客户消息 |
| N05 | 问诊采集（8问槽位） | 步骤3 | 🤖 **Intake** | 状态=已开口且已确认诉求 |
| N06 | 病历摘要生成 | 步骤4 | 🤖 Charting → 🧑 确认 | 槽位填充率 ≥ 阈值 |
| N07 | 诊断结论发布 | 步骤4 | 🧑 **人工/药师** | 摘要经客户确认 |
| N08 | 用药方案生成 | 步骤5 | 🤖 草稿 → 🧑 **药师审批** | 结论已发布 |
| N09 | 依从性提要求 | 步骤6 | ⚙️ 规则模板 | 方案已发布 |
| N10 | 案例匹配推送 | 步骤7 | 🤖 CaseMatch | 客户确认理解方案 |
| N11 | 报价 | 步骤8 | ⚙️ 规则 + 🧑 | 案例已推送 |
| N12 | 异议应答 | 五 | 🤖 **Objection RAG** | 任意阶段检出疑虑意图 |
| N13 | 成交信号识别与逼单提示 | 九 | 🤖 **SignalDetector** | 每 3 轮对话滚动评估 |
| N14 | 沉默唤醒 | 二 | 🤖 Revival | 报价后 N 小时无回复 |
| N15 | 收址收款 | 步骤9–10 | 🧑 **人工** | 客户表达成交意愿 |
| N16 | 5 次交接铺垫 | 步骤11 | ⚙️ 规则触发 + 🤖 文案适配 | 定金到账 / 留痕 / 签收 / 教用法 |
| N17 | 会话质检与复盘 | — | 🤖 QAReviewer | 会话闭环或每日批处理 |

旁路网关：
- **G1 合规守门**：N01–N16 所有对外文本的**唯一出口**，不可绕过。
- **G2 标签与画像**：贯穿全流程，实时写回 6 章的 5 组标签。

## 2. 会话状态机

流程标签（第六章）天然就是状态定义，直接拿来做 FSM：

```
                    ┌──────────── 无效/禁开发 (X) ────────────┐
                    │  同行·媒体·小孩·90岁以上·重症·未成年     │
                    └─────────────────▲───────────────────────┘
                                      │ N04 判定
  [S0 NEW]──N01──▶[S0 已加未开口]
       │                │
       │  N02 当天3次     │  N03 第2–4天三封信
       │  ▼              ▼
       └────────▶[S1 有效开口]──N05──▶[S2 信息收集中]
                                          │ 槽位 ≥ 80%
                                          ▼
                                    [S3 已下结论] ──N08──▶ [S4 已出方案]
                                          ▲(药师审批)          │
                                          │                    ▼ N09/N10
                                          │              [S5 提要求/给信心]
                                          │                    │ N11
                                          │                    ▼
                                    [S8 报价后沉默] ◀──超时── [S6 已报价]
                                          │ N14 唤醒            │ N15
                                          └────────────────────▶▼
                                                          [S7 已成交]
                                                                │ N16 ×5
                                                                ▼
                                                          [S9 已交接医助]
```

**状态与标签的绑定关系**（Morphix 落库时一一对应）：

| FSM 状态 | 流程标签（必选） | 层级标签 | 允许的自动化等级 |
|---|---|---|---|
| S0 | 未开口 | — | 全自动 |
| S1 | — | A 重点挖掘 | 全自动 |
| S2 | 客户信息收集 | A | 全自动（AI 主问） |
| S3 | 下结论出方案 | A | **人工确认后发送** |
| S4 | 下结论出方案 | A | **药师审批后发送** |
| S5 | 提要求 / 给信心发案例 | A | 半自动 |
| S6 | 报价 | A/B | **人工发送** |
| S8 | 报价 | B/C/D（按天数漂移） | AI 起草 + 人工确认 |
| S7 | 成交 | — | 人工 |
| S9 | — | — | 规则触发 |

层级标签按进粉天数自动漂移：`≤30天=A｜30-60=B｜60-90=C｜>90=D`，这是纯规则，不要浪费 LLM 调用。

## 3. 智能体分工（10 个 Agent）

```
                         ┌─────────────────────────┐
   企微消息入站 ────────▶ │  A0  会话主控 Router    │  判断当前状态 + 下一动作
                         └───────────┬─────────────┘
                                     │ dispatch
   ┌──────────┬──────────┬───────────┼───────────┬──────────┬──────────┐
   ▼          ▼          ▼           ▼           ▼          ▼          ▼
 A1 破冰   A2 问诊    A3 病历      A4 异议     A5 信号    A6 沉默   A7 交接
Icebreaker  Intake   Charting   Objection   Signal     Revival  Handover
   │          │          │           │           │          │          │
   └──────────┴──────────┴─────┬─────┴───────────┴──────────┴──────────┘
                               ▼
                    ┌─────────────────────┐
                    │ G1  A8 合规守门 Gate │  ← 唯一出口，PASS/REWRITE/BLOCK
                    └──────────┬──────────┘
                               ▼
                        企微出站 / 人工待办队列
                               │
   旁路：A9 标签画像 Tagger ────┴──── A10 质检 QAReviewer（离线）
```

| Agent | 何时该用 AI（而不是模板） | 模型建议 | 是否可直发客户 |
|---|---|---|---|
| A0 Router | 状态判定涉及语义（如"这算有效开口吗"） | 小模型/快模型 | 否（只做调度） |
| A1 Icebreaker | 需按客户画像选内容 + 控节奏 | 中模型 | 是（过 A8） |
| A2 Intake | **8 问的追问、澄清、槽位归一化** | 中模型 | 是（过 A8） |
| A3 Charting | 从散乱对话抽结构化病历 | 中模型 | **否，人工确认** |
| A4 Objection | **25 类异议 RAG 检索 + 场景化改写** | 中/大模型 | 是（过 A8） |
| A5 Signal | 5 类购买信号检测 + 逼单时机 | 小模型 | 否（给客服看板提示） |
| A6 Revival | 沉默归因 + 唤醒策略选型 | 中模型 | 起草，人工确认 |
| A7 Handover | 5 次铺垫的文案个性化 | 小模型 | 是（过 A8） |
| A8 Compliance | **合规规则 + 语义判断，必须旁路** | 中模型（低温） | 网关 |
| A9 Tagger | 5 组标签自动分类 | 小模型 | 否（写库） |
| A10 QAReviewer | 会话质量打分、SOP 执行率 | 大模型（离线批） | 否（报表） |

**不该用 AI 的地方（省钱且更稳）**：
- 欢迎语、依从性忌口告知、层级标签漂移、跟进定时器 → 纯模板/定时任务。
- 报价数字、优惠额度、定金金额 → 配置表，**绝不让模型生成数字**。

## 4. 知识底座（RAG 三库）

| 库 | 来源 | 切片策略 | 被谁检索 |
|---|---|---|---|
| **KB-QA 异议库** | 第五章 25 类 | 一问一答一片，带 `疑虑标签` 元数据 | A4 |
| **KB-MED 医学库** | 第八章 8.1–8.15 | 按小节切，带 `病种/症状` 元数据 | A2、A3、A4 |
| **KB-PERSONA 画像库** | 第七章 | 按画像类型切 | A1、A6、A9 |
| **KB-CASE 案例库** | 案例1–8 + 月度案例精选 | 一案一片，带 `年龄/性别/病程/症状` 元数据 | A10（案例匹配） |

检索必须带**元数据过滤**再做向量召回，否则「耳鸣+失眠」会召回一堆「中耳炎」内容。

## 5. 合规红线（必须先看这一节）

这份 SOP 里有一批话术，**由真人说是销售话术，由 AI 自动发送就是可批量取证的违规证据**。上 AI 之前必须处理，否则规模化只会放大风险。

| 风险项 | 原文出处 | 风险类型 | 处理建议 |
|---|---|---|---|
| "久鸣必聋，久聋必呆" | 步骤3、二、24 | 恐吓式营销 / 医疗断言 | **A8 硬拦截**，改为中性风险提示 |
| "从根本上清除耳鸣耳聋" | 步骤5 | 疗效保证 | 硬拦截，改"辅助改善" |
| "发现一例虚假，愿承担所有责任" | 5.2、18.2 | 绝对化承诺 | 硬拦截 |
| "昨夜 23:47 有位用户说…" | 四·第2天 | **虚构事实**（文档自述"精准时间戳强化真实感"） | **禁止 AI 生成**，全部下线 |
| "监测到您符合肝郁气滞型初筛特征" | 四·第4天 | 无依据的伪诊断 | 硬拦截 |
| "指定每地区 100 名优惠名额""名额满即止" | 步骤8、四 | 虚假优惠 / 人造稀缺 | 需真实活动备案才可用 |
| "我是健康顾问/客服"但执行问诊与开方 | 步骤3–5、20 | 无资质诊疗 | **N07/N08 强制药师签字** |
| 开口率 21%→49%、投诉率降 82% 等数据 | 三、四 | 引用无出处 | 不得对客户输出 |

**架构层面的三道锁**：
1. **A8 合规守门是唯一出口**——任何 Agent 都不能直连企微发送通道。
2. **N07/N08/N11/N15 四个节点设 Human-in-the-loop**，AI 产物进待办队列，人工点「发送」才出去。
3. **全量留痕**——每条 AI 生成内容记录 `agent_id / prompt_version / model / 检索命中片段 / 合规判定`，出问题能回溯到具体提示词版本。

> 直说：把「下结论 + 出方案」交给 AI 自动发送，是这套流程里唯一可能把公司搞进大麻烦的设计。其余环节自动化都很安全。

## 6. 落地路线（建议三期）

| 期 | 范围 | 交付 | 验收指标 |
|---|---|---|---|
| **一期（低风险高回报）** | A9 标签 + A4 异议应答 + A5 信号检测，全部「副驾模式」（只给客服提示，不自动发） | 客服侧边栏推荐话术 | 标签准确率 ≥90%；客服采纳率 ≥40% |
| **二期** | A1 破冰 + A2 问诊 + A6 沉默唤醒，开启自动发送（过 A8） | 未开口客户全自动跟进 | 24h 开口率提升；A8 拦截率 <5% |
| **三期** | A3 病历 + A7 交接 + A10 质检，接入药师审批流 | 病历自动成稿、交接零漏铺垫 | 病历人工修改率 <30%；铺垫完成率 100% |

**永不自动化清单**：诊断结论发布、用药方案、价格/优惠、收款、退换货承诺。

## 7. 度量指标

| 层 | 指标 | 口径 |
|---|---|---|
| 流程 | 各状态停留时长、状态跃迁率 | S0→S1、S2→S3、S6→S7 |
| AI | 提示词版本 A/B 转化差、A8 拦截率、RAG 命中率 | 按 `prompt_version` 分组 |
| 质量 | SOP 执行完整率（11 步做了几步）、铺垫 5 次完成率 | A10 离线批 |
| 合规 | 违规话术发出数（应为 0）、人工闸门绕过数（应为 0） | 审计日志 |
